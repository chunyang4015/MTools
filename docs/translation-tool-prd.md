# 翻译命名工具 — 需求分析文档

## 1. 功能概述

为开发者提供中文→英文变量命名翻译工具。输入中文描述，通过本地大模型翻译为英文，并自动生成多种命名格式（camelCase、PascalCase、snake_case、SCREAMING_SNAKE_CASE、kebab-case），一键复制。

支持三种模型来源：外部服务（Ollama/LM Studio 等）、本地模型文件（用户自行下载的 GGUF）、内置下载（MTools 直接下载模型并内嵌推理）。

## 2. 用户场景

| 场景 | 输入 | 输出 |
|------|------|------|
| 写代码时变量命名 | `用户名` | `userName`、`UserName`、`user_name`、`USER_NAME`、`user-name` |
| 函数命名 | `获取用户信息` | `getUserInfo`、`GetUserInfo`、`get_user_info`、`GET_USER_INFO`、`get-user-info` |
| 类名/组件名 | `订单详情` | `orderDetail`、`OrderDetail`、`order_detail`、`ORDER_DETAIL`、`order-detail` |
| 常量命名 | `最大重试次数` | `maxRetryCount`、`MaxRetryCount`、`max_retry_count`、`MAX_RETRY_COUNT`、`max-retry-count` |

## 3. 功能需求

### 3.1 翻译工具（核心）

**ID**：`translator`
**关键词**：`translate`, `翻译`, `命名`, `naming`, `变量`, `variable`, `camel`, `snake`

#### 输入

- 中文输入框，支持多行输入（如「获取用户信息 根据用户ID」）
- 输入后自动触发翻译（防抖，避免频繁调用模型）
- 支持剪贴板粘贴

#### 输出

翻译结果以**命名格式卡片**形式展示，每种格式一行：

```
┌──────────────────┬──────────────────────────┐
│  输入框           │  翻译结果                  │
│  （左侧）         │  camelCase  userName [复制]│
│                  │  PascalCase UserName [复制]│
│                  │  ...                      │
└──────────────────┴──────────────────────────┘
```

左右双列弹性布局：左侧输入区 + 右侧结果区，自适应填充面板高度。

- 每行格式：格式名称 + 命名结果 + 复制按钮
- 点击复制按钮后，按钮文字短暂变为「已复制」
- 格式名称可点击，复制该格式的值

#### 多结果支持

当输入较复杂时（如「用户管理和权限验证」），模型可能返回多个翻译建议：

```
  ── 建议 1 ──
  camelCase      userManagerAndAuth   [复制]
  ...

  ── 建议 2 ──
  camelCase      userAdminAndPermission  [复制]
  ...
```

#### 底部工具栏

| 按钮 | 功能 |
|------|------|
| 翻译 | 手动触发翻译 |
| 清空 | 清空输入和结果 |
| 设置 | 展开/收起工具内设置面板 |

### 3.2 工具内设置

翻译工具内置独立的设置面板，用户点击工具栏齿轮图标展开/收起：

```
┌─────────────────────────────────────────┐
│  ⚙ 直达快捷键                            │
│   [点击录入快捷键]          (默认：无)    │
│                                         │
│  命名格式                                │
│   ☑ camelCase   ☑ PascalCase            │
│   ☑ snake_case  ☑ UPPER_SNAKE           │
│   ☑ kebab-case                           │
└─────────────────────────────────────────┘
```

#### 直达快捷键

- **默认不绑定**，用户自行录入（与主快捷键录入交互一致：点击输入框 → 按下组合键 → 自动保存）
- 功能：按下直达快捷键后，**跳过搜索框**，直接打开翻译工具面板
- 快捷键注册通过 Rust 后端 `register_tool_shortcut` 命令实现
- 支持 Esc 关闭，再次按下同一快捷键也可关闭

#### 命名格式

- 默认全选 5 种格式
- 取消勾选后，翻译结果中不再展示该格式

#### 配置持久化

- 命名格式：localStorage `mtools:translator:formats`
- 直达快捷键：存入全局配置（Rust 管理），因为全局快捷键需在应用层面注册

```json
{
  "shortcut": "Alt+Space",
  "auto_start": false,
  "llm": { "..." : "..." },
  "tool_shortcuts": {
    "translator": "Cmd+T"
  }
}
```

### 3.3 剪贴板检测

当剪贴板包含中文字符时（至少 2 个中文字符），提示翻译工具：

- 检测规则：剪贴板文本匹配 `/[一-鿿]{2,}/`
- 提示文案：`「{剪贴板内容前10字}...」可以翻译为变量命名`
- 进入工具后自动填入剪贴板内容并触发翻译

### 3.4 模型状态提示

翻译工具内需展示模型状态：

| 状态 | 展示 |
|------|------|
| 模型未配置/未下载 | 提示文案 + 跳转设置按钮 |
| 模型加载中 | Loading 状态 |
| 模型就绪 | 正常使用 |
| 推理中 | 翻译按钮/结果区 Loading 动画 |

## 4. 设置页面扩展

现有设置页面新增 **「AI 模型」** 分类。此分类为**共享基础设施**，翻译工具、后续的本地聊天等功能均复用此配置。

### 4.1 三种模型来源

MTools 支持三种方式获取模型能力，用户按需选择：

| 来源 | 适用场景 | 设置项 |
|------|----------|--------|
| **外部服务** | 已安装 Ollama / LM Studio 等 | 服务地址 + 模型下拉选择 |
| **本地模型路径** | 用户自己下载了 GGUF 文件 | 本地文件路径（如 `~/models/qwen.gguf`） |
| **内置下载** | 什么都没有，开箱即用 | 推荐列表 → 一键下载到 `~/.mtools/models/` |

三种来源最终都汇聚到同一个 `translate_to_naming` 接口，只是底层走 HTTP API 还是本地推理。

### 4.3 运行时选择

下拉菜单选项：

| 选项 | 行为 |
|------|------|
| **自动检测** | 按优先级检测：内嵌本地模型 → Ollama → LM Studio，使用第一个可用的 |
| **Ollama** | 手动指定 Ollama 服务地址 |
| **LM Studio** | 手动指定 LM Studio 服务地址 |
| **内嵌引擎** | MTools 自己跑推理，需配置本地模型路径或下载模型 |

### 4.4 外部服务模式

选择 Ollama / LM Studio / 自定义时：

1. 展示服务地址输入框 + 模型下拉选择
2. 「自动检测」按钮：扫描 localhost 常见端口，找到运行时后自动填充地址和模型列表
3. 「测试连接」按钮：发送简短请求验证模型可用
4. 模型列表从运行时 API 实时拉取（Ollama `/api/tags`，OpenAI 兼容 `/v1/models`）

### 4.5 内嵌引擎模式

选择「内嵌引擎」时：

#### 本地模型路径

- 文件路径输入框 + 「选择文件」按钮（打开 macOS 文件选择器，筛选 `.gguf` 文件）
- 输入路径后自动验证：文件存在 → 检查 GGUF 头部格式 → 显示「✅ 模型可用」或「❌ 文件无效」
- 验证通过后自动保存，翻译工具直接使用此模型
- 用户配置了本地路径则**优先使用本地模型**，无需下载

#### 内置下载

当本地路径为空时，展示推荐模型列表（突出显示，引导用户下载）：

| 模型 | 量化 | 大小 | 说明 |
|------|------|------|------|
| Qwen2.5-3B-Instruct | Q4_K_M | ~2GB | 推荐平衡点 |
| Qwen2.5-1.5B-Instruct | Q4_K_M | ~1GB | 轻量级，适合简单翻译 |
| Qwen2.5-7B-Instruct | Q4_K_M | ~4GB | 高质量翻译 |

- 点击下载后，从 HuggingFace 下载 GGUF 文件到 `~/.mtools/models/<model-name>.gguf`
- 下载进度展示（百分比 + 进度条 + 已下载/总大小）
- 下载完成后自动填充到本地模型路径
- 已下载模型列表展示在下方，支持删除释放磁盘空间

#### 模型管理

- 已下载模型展示在设置页底部：文件名 + 大小 + 删除按钮
- 删除前确认（模型文件较大）
- 删除 = 删除文件 + 清空配置中的本地路径（如果指向该文件）

### 4.6 运行时检测（自动检测模式）

应用启动时自动检测本机可用的 LLM 运行时：

| 优先级 | 运行时 | 检测方式 |
|--------|--------|----------|
| 1（最高） | 内嵌本地模型 | 检查配置中 `llm.local_model_path` 指向的文件是否存在且为有效 GGUF |
| 2 | Ollama | 检测 `http://localhost:11434/api/tags` 是否可访问 |
| 3 | LM Studio | 检测 `http://localhost:1234/v1/models` 是否可访问 |
| 4（兜底） | 无 | 提示用户配置或下载模型 |

检测到后自动填充对应配置。未检测到任何可用来源时，显示配置引导。

### 4.7 配置持久化

全局配置（`~/Library/Application Support/com.mtools.app/config.json`）：

```json
{
  "shortcut": "Alt+Space",
  "auto_start": false,
  "llm": {
    "runtime": "auto",
    "api_url": "http://localhost:11434",
    "model": "qwen2.5:latest",
    "local_model_path": ""
  },
  "tool_shortcuts": {
    "translator": "Cmd+T"
  }
}
```

- `runtime`：`auto` | `ollama` | `lmstudio` | `embedded`
- `api_url`：外部服务的 API 地址
- `model`：外部服务的模型名称
- `local_model_path`：内嵌引擎的本地 GGUF 文件绝对路径

工具级配置（localStorage，各工具自管）：

- 翻译命名格式：`mtools:translator:formats` → `["camelCase", "PascalCase", "snake_case", "UPPER_SNAKE_CASE", "kebab-case"]`

## 5. 技术方案分析

### 5.1 推理方案对比

内嵌引擎有两个候选方案：

| 方案 | Apple Silicon 优化 | 集成复杂度 | 依赖大小 | 模型格式 | 推荐度 |
|------|:------------------:|:----------:|:--------:|:--------:|:------:|
| **llama.cpp（内嵌）** | ✅ Metal | 中（`llama-cpp-rs` crate 成熟） | ~30MB | GGUF | ⭐⭐⭐⭐⭐ |
| **MLX Swift（内嵌）** | ✅ 原生 | 高（需 ObjC FFI 桥接） | ~50MB | safetensors | ⭐⭐⭐⭐ |

**推荐 llama.cpp 路线**：

- `llama-cpp-rs` Rust crate 已被多个项目验证，API 稳定
- GGUF 格式在 HuggingFace 上模型丰富，直接下载可用
- Metal 加速性能好，翻译场景（短文本）与 MLX 差距可忽略
- 不需要额外的 Swift/ObjC 桥接层（项目已有 clipboard/icon 的 ObjC 模式，但推理场景复杂度高得多）

### 5.2 分层架构

```
┌──────────────────────────────────────────────────┐
│                   工具层 (JS)                     │
│  ┌──────────┐  ┌──────────┐  ┌────────────────┐  │
│  │ 翻译工具  │  │ 聊天工具  │  │  未来更多工具…  │  │
│  │ (命名格式 │  │ (对话历史 │  │                │  │
│  │  独立配置) │  │  独立配置) │  │                │  │
│  └─────┬────┘  └─────┬────┘  └───────┬────────┘  │
└────────┼──────────────┼───────────────┼───────────┘
         │              │               │
         └──────────────┼───────────────┘
                        │ Tauri Command
┌───────────────────────▼──────────────────────────┐
│           Rust 推理调度层（共享）                   │
│                                                   │
│  runtime == "embedded" && local_model_path 有效？  │
│     ├─ 是 → llama.cpp 本地推理                    │
│     └─ 否 → HTTP API（Ollama / LM Studio / 自定义）│
└───────────────────────┬──────────────────────────┘
                        │
┌───────────────────────▼──────────────────────────┐
│             模型管理层                             │
│  下载 / 验证 / 加载 / 卸载                        │
│  ~/.mtools/models/                                │
│  本地路径指向（用户自选 GGUF 文件位置）            │
└──────────────────────────────────────────────────┘
```

> **设计原则**：AI 模型配置（运行时、地址、模型选择、本地路径）由全局设置页统一管理，所有工具共享。各工具的专属设置（翻译的命名格式、聊天的对话历史等）由工具自身管理，存 localStorage。

**推理调度逻辑**：

1. 根据 `llm.runtime` 配置选择推理后端
2. `auto` 模式：按优先级检测可用后端（内嵌本地模型 → Ollama → LM Studio）
3. `embedded` 模式：
   - 如果 `local_model_path` 非空且文件有效 → 用该文件
   - 否则 → 检查 `~/.mtools/models/` 下是否有已下载模型
   - 都没有 → 返回「请配置模型」错误
4. 外部 API 模式：通过 HTTP 调用（OpenAI 兼容格式），复用现有 `translate_to_naming` 逻辑

### 5.5 工具直达快捷键架构

**设计原则**：直达快捷键是通用能力，任何工具都可以配置，不限于翻译工具。

```
状态机扩展：
                                      工具直达快捷键（如 Cmd+T）
[隐藏] ──────────────────────────────────────────────────────► [翻译工具面板]
  ▲                                                              │ Esc / 再次按下
  │    全局快捷键/Esc                                              │
  │◄── [翻译工具面板] ◄───────────────────────────────────────────┘
  │
  │    全局快捷键（Alt+Space）
  └──► [搜索栏] ──► ... ──► [任意工具面板]  ← 现有流程不变
```

**实现要点**：

1. `tool_shortcuts` 存在全局配置中（Rust 管理），因为全局快捷键需应用层面注册
2. 每个快捷键注册为独立的 `GlobalShortcut`，回调中直接触发「显示窗口 + 打开指定工具」
3. 打开流程：显示窗口 → 渲染目标工具到 Tab → 跳过搜索框 → 直接进入工具面板
4. 工具的 `destroy()` 后，对应的直达快捷键不受影响（只是下次唤起时重新 `render`）

### 5.6 模型文件管理

```
~/.mtools/
├── models/
│   ├── qwen2.5-3b-instruct-q4km.gguf     ← 内置下载存放位置
│   └── qwen2.5-1.5b-instruct-q4km.gguf
│
│  也支持用户自定义路径（如 ~/models/xxx.gguf），
│  只在 config.json 中记录路径，不移动文件。
```

模型文件格式统一为 GGUF（适用于 llama.cpp）：

- 来源 1：用户自己从 HuggingFace 下载，配置本地路径
- 来源 2：MTools 内置下载，存到 `~/.mtools/models/`
- 两种来源的文件格式相同，内嵌引擎统一处理

## 8. 开放问题

1. **模型推荐列表**：固定列表还是远程配置拉取？固定列表更简单，远程更灵活。
